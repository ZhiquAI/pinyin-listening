# 图片拼音听读闯关网站开发计划

> **执行方式：** 在当前会话按任务逐项实施，使用 `superpowers:executing-plans`。用户本次要求为制定计划；本文不表示产品代码或语音评测已完成。研发沿用项目要求的 `tdd` → `implement` → `code-review`，核心逻辑先复现或写失败测试。

**Goal:** 为一名约六岁的一年级孩子开发图片式拼音听读网站，支持基础复习、即时反馈、每日错误记录、间隔复习和闯关，并通过真实录音验证后接入自动跟读评测。

**Architecture:** 一个适配手机、平板和电脑的网站，儿童练习与家长管理分开。练习记录先保存在当前浏览器，语音评测经服务端适配器调用供应商；练习、掌握程度与评测可用性互相独立。

**Tech Stack（建议，尚未安装）:** Next.js + React + 严格 TypeScript，Zod 定义内容及数据契约，IndexedDB 保存学习事件，Vitest 验证判题及复习逻辑，Playwright 验证关键用户流程。版本在实施时核对兼容性、锁定依赖；不为第一版引入数据库、登录或管理平台。

**Spec:** 本文第 1—5 节是依据本次对话收敛的第一版设计基线；未被用户逐项确定的数值、技术选型和规则均为开发建议，不是已验证的教学效果。

## Global Constraints

- 默认中文，面向约六岁的一年级儿童；图标配文字或声音，不要求孩子先熟练阅读说明。
- 学习范围跟随学校已学内容；完整拼音表可浏览，未学条目不自动进入每日任务。
- 图片用于认识词义；纯听辨测试先隐藏图片、汉字和答案，提交后再显示。
- 拼音显示为 Unicode 带调字母；内部将字形、发音目标和声调分开，不能依靠字符串随意切分音节。
- 整体认读音节按整体认读；ü 的拼写、三拼、轻声和标调位置均需显式规则与例题。
- 首次独立答对、提示后答对、订正答对、家长确认和机器判断分别记录。
- 听辨、拼写、口读、纸上听写分别统计；网页会选不等于会写，口读会读不等于听写掌握。
- 不确定、未录到音、设备异常、服务超时不算学习错误，不扣关卡进度。
- 配置集中管理；密钥只在服务端，禁止放到浏览器包或导出备份中。
- 单孩子、单设备优先；保存范围为同一浏览器及网站地址，提供备份恢复，暂不承诺跨设备同步。
- 保留原始 PDF；试题与音频需校对，听写照片无法确认的目标不可擅自编入“已确认错题”。

## Review Focus

1. 快速连点、重载与恢复备份可能重复累计：按作答 ID 去重，派生统计可重建。
2. 看过提示后切换页面可能被误算独立答对：提示标记随作答持久化。
3. 手机拒绝麦克风、后台切换、录音中断：释放麦克风并保留练习，提供非录音路径。
4. 语音服务将短童声、噪音或示范音误判：独立验证集测试，播放与录音互斥，不确定不判错。
5. 日期跨午夜、时区变化及夏令时导致重复复习：使用 Asia/Shanghai 的日历日期与日期运算，不能只加 24 小时毫秒数。

## 1. 已确认的需求与边界

已确认：图片式听读、每天记录错误、即时反馈、反复强化、闯关；补充基础拼音表；支持老师式拼读示范；希望自动判断孩子跟读是否正确。

建议的第一版操作：孩子独立点选和拼装，家长补充学校错题与纸上听写结果。此操作方式尚未单独确认，实施前以本计划作为可修改默认值。

初始无产品代码。当前目录有第二至第九周的 8 份语文 PDF；本次抽查第二周、第九周文本，未完成全部题目及页面视觉校对。第九周材料包含平翘舌音复习、ai/ei/ui、ao/ou/iu 等后续学习安排。不能把所有资料的全部知识一开始都视为已学。

第一版暂不包含：手写 OCR 自动判卷、开放式口语聊天、无依据的“AI 精确诊断”、自训练语音模型、多人排行榜、商店、支付、账号体系、跨设备同步。自动跟读评测属于目标范围，必须经过验证门槛，不用假分数代替真实接入。

## 2. 页面与练习闭环

### 儿童端

- 首页：今日任务、继续练习、基础拼音馆；优先展示一个主要行动。
- 基础拼音馆：23 个声母、24 个韵母、16 个整体认读音节、四声；清楚区分“字母/韵母”与“整体音节”。
- 学习卡：清晰图片、词义、规范拼音、普通读音、分步拼读；播放片段由课程元数据指定。
- 听辨关：只听音，选择声母、韵母或声调；每题 2—4 个选项，只比较本题目标。
- 拼装关：按课程允许的音节结构选择字母/组件、声调及标调位置，支持改选；整体认读不强制拆拼。
- 跟读关：按住或点击开始录音，再点击结束；显示“正在听／处理中／完成／请重录／待家长确认”。不默认长时间监听。
- 每日结束页：奖励完成练习，具体说明进步；剩余错题进入复习，不以无限重做阻止退出。

### 家长端

- 标记已学范围和今天学校练习内容。
- 查看每日题数、首次独立答对比例、声母/韵母/声调/标调位置/漏写情况，以及不同练习方式的分项表现。
- 录入预期拼音、孩子实际答案或未知错误，预览分类后确认；修改记录保留修订关联，不静默篡改原作答。
- 记录纸上听写结果，和网页成绩分开。
- 家长确认有争议的跟读结果；查看评测可用性与近期待复习内容。
- 导出、预览并恢复带版本号的备份；导入失败时保留当前数据。

## 3. 题库、图片与示范音

第一批建议制作 30 个经过核对的音节/词条，用来走通完整闭环；优先来自已学学校资料与家长确认错题。不是按单张照片猜测题目，也不是生成所有声韵组合。

每个词条包含：稳定 ID、汉字或词语、音节列表、拼写组件、声调、标调目标、教学拆拼步骤、知识标签、所需已学知识、图片、音频、资料来源、校对状态。基础表条目另有类型标记，不要求每个字母强配一张有歧义的图。

内容处理步骤：提取 8 份 PDF 的听写条目 → 按原页核对 → 标明周次及学习先后 → 区分已学与预告 → 人工确认拼音、轻声、多音字和配图含义 → 进入已校对题库。

图片采用统一儿童插画，目标对象明确；使用来源清楚的素材或后续授权生成，登记来源。初版先校对少量代表词条，确认风格后扩展。

示范音优先使用经核对的普通话录音或可控发音合成。不能直接让浏览器照英文习惯朗读拼音字母。以“火”为例，演示发音与分步教学需单独审核；“h、u、o → huo → 三声 → huǒ”的老师式步骤作为可配置教学内容，不将其直接当成普通汉字朗读送测。

标调规则至少覆盖：a 优先、其次 o/e、iu/ui 标末尾，以及 i 上标调去点。ü 在 j/q/x/y 后的拼写规则用显式元数据，不用简单替换；补充 nü、lǜ、ju、yu、yue、yuan 等用例。轻声以单独状态表示，不能算“漏调”。

## 4. 记录、复习与闯关规则（建议初始值）

- 每日约 5—10 分钟：基础复习约 2 分钟，其余完成 8 道主任务，允许提前结束，不设倒计时惩罚。
- 每日 8 题优先选择 4 道到期复习、2 道当前易混专项、2 道已学巩固或学校新题；不足时以其他已学题补足，不跨出已学范围、不反复用同题凑数。题库不足时允许少于 8 题。
- 每个知识点按练习方式分别保存状态：未练、练习中、待复习、暂时掌握。误差标签允许同时出现，例如声母和声调都错。
- 第一次作答错误：生成对应专项；至少间隔 2 道其他题后再回测一次，当日同目标最多主动重复 2 次，避免无限循环。
- 首次或订正后正确：不立即授予掌握；后续按日历日期安排第 1、3、7 天复习，答错后从次日重新安排。
- 同一目标在同一练习方式下，3 个不同日期独立答对，才标记“暂时掌握”；提示、订正、无结论的机器评测不计入。
- 日任务完成奖励与掌握认证分开；不能依靠连续点提示或反复提交刷过掌握关。
- 家长确认口读可以作为口读证据，但来源明确；纸上听写证据单列，不混为网页答题或自动评测。
- 以上是软件可测试的初始策略，不代表已证实的最优学习间隔。规则版本入库，后续按孩子试用调整。

## 5. 自动跟读评测：先验证，再接入

### 候选路线与依据

优先小样验证讯飞中文语音评测流式接口：官方文档提供中文单字、词语题型、面向小学群体的参数，以及声韵/调型错误信息选项。基础录音需求为 16 kHz、16 bit、单声道。不能因文档有字段就保证六岁童声或分步拼读可用。

官方来源（2026-10-26 查阅）：
- [讯飞语音评测流式 API](https://www.xfyun.cn/doc/Ise/IseAPI.html)
- [讯飞试题格式与结果说明](https://www.xfyun.cn/doc/voiceservice/ise/ise_protocol.html)

旧普通版接口已下线，不能照旧教程开发。调型字段可能描述预期目标而不是孩子实际发音；必须依据官方错误信息及实测结果映射，禁止拿目标拼音伪装为识别结果。字段缺失时返回“该维度未评测”，不能默认正确。

### 验证范围和放行门槛

1. 先验证指定汉字/词语对应的完整音节跟读；再单独验证声母、韵母孤立发音，以及“拆拼＋报第几声＋完整音节”的整段朗读。三类能力独立报告。
2. 开发阶段用成年人的测试录音走通技术链路；儿童录音上传前向家长说明供应商、用途和保留策略，取得明确同意。不默认上传这次对话的语音。
3. 小样至少 60 条：20 条核对正确、20 条带已知错误、10 条静音/噪音/中断、10 条重复录制。覆盖四声、二三声易混、声母差异、前后鼻音；以成人样例为主只证明技术链路，不能据此宣布适合孩子。
4. 分开校准与验证录音；同一录音不同时用于选阈值和验收。孩子在常用设备上的自然正确读音必须进入独立验证集，并由家长或教师确认；标签有争议归“待确认”。
5. 建议放行标准：验证集中正确读音误判为错不超过 5%，已知错误的检出率至少 80%，可给明确结论的有效录音占比至少 80%；每项报告分子/分母。小样仅支持家庭试用，不宣称总体准确率。
6. 未通过某个维度时，只开放已通过的能力；不能通过大量返回“待确认”假装评测准确。明确反馈“声母错／韵母错／声调错”还需该维度单独有已标注错例验证。
7. 服务返回失败、缺字段、拒评或无可靠结论，均不写入错误或掌握证据。跟读关可由家长确认完成，不能让设备问题阻塞整天练习。

体验目标：录音结束后立即显示处理中；有效网络下以真实数据记录响应分布，争取大多数请求 5 秒内返回。单次服务截止 15 秒，超时转为重试/家长确认，不重复自动收费调用。具体费用和免费额度在真实账户开通时再核对，不在计划中承诺免费。

原始儿童录音默认只在内存中处理，不在本项目服务端长期保存；外部供应商保留策略须另外核对。为了人工校准确需保存录音时，单独说明并取得家长同意；正常练习只保存结果摘要。

## 6. 文件职责与核心接口

所有以下路径相对于当前项目；这是拟创建结构，不表示已有代码。

| 文件/目录 | 职责 |
| --- | --- |
| `src/app/page.tsx` | 今日任务入口 |
| `src/app/basics/page.tsx` | 基础拼音馆 |
| `src/app/practice/page.tsx` | 学习、听辨、拼装和跟读流程 |
| `src/app/parent/page.tsx` | 已学范围、错题录入、报告和备份 |
| `src/content/schema.ts`、`pinyin.ts`、`items.ts` | Zod 内容契约、基础表、已核对词条 |
| `src/features/practice/grading.ts`、`session.ts` | 确定性判题与作答状态，不调用供应商 |
| `src/features/review/scheduler.ts` | 每日组题、到期与掌握计算 |
| `src/features/progress/schema.ts`、`repository.ts` | 事件契约、IndexedDB 读写、去重与备份 |
| `src/features/speech/contracts.ts`、`recorder.ts` | 评测契约、录音与格式转换 |
| `src/server/speech/xfyun-adapter.ts` | 供应商鉴权、音频分帧、响应映射 |
| `src/app/api/speech/assess/route.ts` | 同源评测接口、输入校验、超时和使用限制 |
| `src/config/learning.ts`、`speech.ts` | 有版本号的学习策略及服务端配置 |
| `public/images/`、`public/audio/` | 已校对的图片与示范音 |
| `tests/`、`e2e/`、`docs/qa/` | 核心逻辑测试、用户流程、真实设备与录音验证报告 |

核心契约由 Zod 推导 TypeScript 类型，避免手写两份模型：

- `LearningItem`：id、kind、syllables、requiredSkills、teachingSteps、assetRefs、source、reviewStatus。
- `Attempt`：id、sessionId、itemId、mode、submittedAnswer、errors、hintUsed、evidenceSource、outcome、occurredAt、localDate、policyVersion。
- `ErrorDimension = initial | final | tone | tonePlacement | omission | syllableOrder`。整题或目标不明的家长记录保留“未分类”，不强制套进这几类。
- `Outcome = correct | incorrect | uncertain | invalid`；`evidenceSource = deterministic | machine | parent`。
- `gradeAttempt(item: LearningItem, answer: StructuredAnswer): GradingResult`：支持多维错误，明确已评测和未评测维度。
- `buildDailySession(input: DailySessionInput): DailySession`：输入含已学范围、已发生事件、策略和当前上海日历日。
- `recordAttempt(attempt: Attempt): Promise<void>`：按 ID 幂等；修订通过关联新事件实现。
- `exportProgress(): Promise<ProgressBackup>`；`importProgress(backup: unknown): Promise<ImportSummary>`：先校验、预览合并、按 ID 去重、事务写入；失败无部分覆盖。
- `assessSpeech(input: SpeechInput): Promise<SpeechAssessment>`：供应商以统一契约返回确定结论、待确认、音频无效或服务不可用；缺少的维度保留未评测。
- 服务端 `POST /api/speech/assess`：接收题目 ID、请求 ID 与 WAV 音频；目标文本由服务端题库查找，不相信客户端传入任意供应商请求。限制 10 秒、1 MB 以内，按实际解码验证；返回统一评测契约及可重试状态。同步交付 OpenAPI 文档。

## 8. 交付顺序与依赖

1. 先完成 Task 1—4，交付真实可用的基础复习、听辨拼装、记录和复习闭环。
2. Task 5 的语音小样尽早开始，避免最后才发现供应商不适用；不依赖它阻塞非语音练习，但不能因此把整体需求宣布全部完成。
3. Task 5 达到验证门槛后执行 Task 6；若不达标，给出失败样例及替代供应商验证建议，再决定下一步，不以普通转文字接口顶替。
4. Task 7 完成自动化与真实设备验收后交付试用版，记录孩子使用反馈再调节题量和复习策略。

计划不承诺固定上线日期：主要不确定项是示范音校对、实际童声评测和常用设备测试。实施时先交付一个小闭环让家长体验，再扩充内容。

## 9. 实施前后的必要输入

- 可立即开展：本地工程、PDF 校对、题库结构、点选判题、记录与复习逻辑。
- 开发初期确认：孩子主要使用设备、当前已学范围；未确认时采用手机/平板自适应、学校资料标注的保守范围，并允许家长修改。
